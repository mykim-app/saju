# 사주풀이 사이트

이름·성별·생년월일·태어난 시각을 넣으면 사주팔자와 풀이를 보여 주는 사이트입니다.
GitHub Pages로 올리고, 기록 저장과 관리자 로그인은 **MBTI 사이트와 같은 Supabase 프로젝트**를 함께 씁니다.

- 첫 화면 맨 아래에 "오늘 사주를 본 사람 N명"이 표시됩니다(한국 시간 자정 기준).
- 화면 오른쪽 아래 작은 회색 점을 누르면 관리자 화면으로 갑니다.
- 관리자 로그인은 MBTI 사이트와 같습니다. 메일로 받은 8자리 인증번호로 들어가며, 20분 동안 조작이 없으면 자동으로 나가집니다.

---

## 1. 설치 순서

### ① 저장소 만들기
1. GitHub에서 새 저장소를 만듭니다(예: `saju`). 공개(Public)로 만들어야 무료로 Pages를 쓸 수 있습니다.
2. 이 폴더 안의 파일을 **폴더 구조 그대로** 올립니다. `index.html`이 저장소 맨 위에 있어야 합니다.

### ② 접속 정보 넣기
`assets/config.js`를 열어 두 줄을 채웁니다. MBTI 저장소의 `assets/config.js`에 있는 값을 그대로 복사하면 됩니다.

```js
export const SUPABASE_URL = "https://xxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJ...";
```

anon 키는 공개용이라 저장소에 올려도 괜찮습니다. **service_role 키는 절대 넣지 마세요.**

### ③ 데이터베이스 설정
1. Supabase 관리 화면 → 해당 프로젝트(MBTI와 같은 곳) → **SQL Editor**
2. `supabase/schema.sql` 내용을 붙여 넣고 **Run**
3. 결과에 오류가 없으면 끝입니다. 여러 번 실행해도 기존 기록은 지워지지 않습니다.

이 스크립트가 하는 일은 다음과 같습니다.

| 항목 | 내용 |
|---|---|
| 관리자 명단(`admins`) | MBTI 때 만든 것이 있으면 **그대로 둡니다** |
| 관리자 확인 함수(`is_admin`) | 있으면 그대로 두고, 없을 때만 만듭니다 |
| 사주 기록 표(`saju_results`) | 새로 만듭니다. 누구나 등록만 가능, 조회·삭제는 관리자만 |
| 한자 이름 칸(`hanja_name`) | 기존 표가 있으면 칸만 더합니다 |
| 오늘 인원 함수(`saju_today_count`) | 숫자만 돌려주고 이름 등 내용은 내주지 않습니다 |
| 궁합 기록 표(`gunghap_results`) | 새로 만듭니다. 두 사람 몫을 한 줄에 저장하며, 권한은 사주 기록 표와 같습니다 |
| 관계 유형 칸(`rel_type`) | 기존 표가 있으면 칸만 더합니다(기본값 연인·부부) |
| 오늘 궁합 인원 함수(`gunghap_today_count`) | 숫자만 돌려줍니다 |

MBTI 표(`mbti_results` 등)와 권한은 건드리지 않습니다.

### ④ 관리자 주소
MBTI 사이트에서 이미 관리자 주소를 등록했다면 **따로 할 일이 없습니다.** 같은 주소로 로그인하면 됩니다.
확인하려면 SQL Editor에서 실행해 봅니다.

```sql
select email from public.admins;
```

새로 등록할 때만 아래 한 줄을 SQL Editor에서 따로 실행합니다. 이 줄은 저장소 파일에 넣지 마세요.

```sql
insert into public.admins (email) values ('관리자-메일-주소') on conflict (email) do nothing;
```

### ⑤ GitHub Pages 켜기
저장소 → **Settings → Pages** → Source를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`로 두고 저장합니다.
1~2분 뒤 `https://<GitHub 아이디>.github.io/saju/`로 접속됩니다.

## 2. 계산 방식

풀이의 정확도는 만세력 계산에 달려 있어 아래 기준을 따릅니다.

| 항목 | 기준 |
|---|---|
| 년주·월주 | 입춘 등 절기가 시작되는 **시각** 기준(날짜만 보지 않음) |
| 일주·시주 | 태어난 곳의 경도로 보정한 실제 태양 시각 기준(서울은 약 32분 늦춤) |
| 표준시 변경 | 1954~1961년(UTC+8:30), 서머타임(1948~1960년 사이 여러 해, 1987~1988년)을 자동 반영 |
| 음력 | 한국천문연구원 자료 기반으로 변환(중국 음력과 윤달이 다른 해가 있음) |
| 밤 11시~자정 | 기본은 다음 날 자시로 봄. "야자시" 칸을 켜면 당일 일주 유지 |
| 시각 모름 | 시주를 빼고 6글자로 풀이 |
| 용신 | 일간의 힘(신강·신약)을 점수로 따져 돕거나 덜어 주는 오행을 고름(억부법) |

계산에는 두 공개 라이브러리를 저장소에 함께 넣어 두었습니다(인터넷 연결 여부와 상관없이 동작).

- `lunar-javascript` 1.7.7 — 절기·간지·대운 계산 (MIT)
- `korean-lunar-calendar` 0.4.0 — 한국 음력 ↔ 양력 변환 (MIT)

절기 시각은 계산 방법에 따라 다른 곳과 몇 분에서 많게는 20~30분까지 차이가 날 수 있습니다(실제로 여러 출처를 대조해 확인한 차이입니다). 거의 모든 경우 결과에 영향이 없지만, 절기가 드는 바로 그 시각 언저리(20~30분 안)에 태어난 경우라면 월주가 다른 곳과 다르게 나올 수 있습니다.

한자 이름 자료는 대한민국 법원 전자가족관계등록시스템의 '인명용 한자 조회'가 공개적으로 내주는 값을 그대로 옮겨 왔습니다(2026년 9월 기준). 원자료(9,494자)에서 유니코드에 실제로 배정되지 않은 코드나 그 조회 화면 전용 글꼴에만 있는 개인용도 영역 코드로 나온 405자는 뺐습니다(어느 글꼴로도 표시할 수 없는 코드라 자료로서 의미가 없었습니다). 남은 9,089자 가운데 기본다국어평면 밖에 있는 아주 드문 한자 50자는 대부분의 기기 글꼴에 그림이 없어 빈 네모로 보이기 쉬워, 후보 목록에는 내놓지 않고 직접 입력했을 때만 인식하게 했습니다. 라이선스 파일은 `assets/vendor/`에 있습니다.

입력 가능한 범위는 양력 1900년~올해, 음력 1900~2050년입니다.

## 3. 풀이에 들어가는 내용

사주 원국 표(천간·지지·십신·지장간·12운성·12신살·납음), 오행 균형, 타고난 성향(일간·띠), 60일주 풀이, 십신 짜임, 일간의 힘과 용신·희신·기신, 행운의 색·숫자·방향, 신살(천을귀인·문창·도화·역마·화개·양인·홍염·괴강·백호·공망), 합·충·형·파·해·원진, 분야별 풀이(성격·재물·직업·연애·건강), 대운 10개, 앞으로 10년 세운, 올해 월운, 오늘의 운세. 맨 앞에는 핵심만 추린 '한눈에 보기'가 있고, 화면 맨 끝에는 그 결과에 나온 한자 용어를 쉬운 말로 풀어 주는 '어려운 말 풀이'가 있습니다(PDF에도 그대로 들어갑니다).

### 한자 이름(선택)

입력 화면에서 한자 이름을 넣으면 결과에 **이름 풀이(한자)** 절이 붙고, '한눈에 보기'에도 한 줄이 들어갑니다. 비워 두면 예전과 똑같이 나옵니다.

- **글자별 획수와 오행**: 획수는 성명학에서 쓰는 원획으로 셉니다. 부수를 획이 줄기 전 본래 글자로 보는 방식입니다(삼수변 氵은 水로 보아 4획, 초두머리 艹는 艸로 보아 6획 등). 끝자리가 1·2면 목, 3·4 화, 5·6 토, 7·8 금, 9·0 수입니다.
- **사격**: 원격(초년)·형격(청년·장년)·이격(중년)·정격(노년·총운) 네 숫자와 각 숫자의 오행을 보여 주고, 사주에 도움이 되는 기운이 드는 시기를 알려 줍니다. 복성(남궁·황보·제갈·선우 등)도 성으로 묶어 계산합니다.
- **소리의 오행**: 이름을 부르는 첫 자음의 오행이 상생으로 이어지는지 봅니다.
- **사주와 맞춰 보기**: 이름 글자의 오행이 이 사주의 용신·희신(도움)인지 기신(조심)인지 알려 줍니다.
- **81수리 길흉은 넣지 않았습니다.** 네 숫자로 길흉을 매기는 표는 문헌과 유파마다 배정이 달라, 어느 한쪽을 골라 단정하지 않기로 했습니다.

한자는 이름과 같은 글자 수, 같은 순서로 넣어야 합니다. 글자 수가 다르거나 대법원 인명용 한자표에 없는 한자가 있으면 그 절에 이유만 알려 주고 사주 풀이는 그대로 보여 줍니다. 한글 이름과 한자 음이 다르면(순서가 바뀐 경우 등) 확인하라는 안내가 뜹니다. 두음법칙(류→유, 리→이)과 金(김)처럼 그 한자로 등록 가능한 다른 음도 맞는 것으로 봅니다. 인명용 호환 한자로 입력해도 같은 글자로 맞춰 계산합니다.

**후보에서 고르기**: 휴대폰에서 한자를 직접 입력하기 어려운 점을 고려해, 한자 칸 옆에 '후보에서 고르기' 단추를 두었습니다. 누르면 이름(한글) 글자마다 그 음으로 읽는 한자 후보를 획수가 적은 순서로 보여 주고, 눌러서 고르기만 하면 한자 칸에 채워집니다. 후보는 대법원 인명용 한자표에 있는 한자만 나오므로, 실제로 이름에 못 쓰는 한자가 섞여 나오지 않습니다. 원하는 글자가 안 보이면 '후보 더 보기'로 더 찾아보거나, 한자를 알면 직접 입력해 주세요. 순 우리말 이름처럼 어느 글자도 한자로 찾지 못하면 안내만 보여 주고 한자 없이 진행해도 됩니다.

한자 약 9,089자의 획수·한글 음 자료가 `assets/hanja-data.js`(약 86KB)에 들어 있습니다. 대법원이 정한 인명용 한자표를 그대로 옮겨 왔고, 출처는 위 '계산 방식' 절에 적었습니다. 대법원이 새로 한자를 추가하면(2~3년 주기로 있어 왔습니다) 이 자료도 다시 받아와야 최신 상태가 유지됩니다.

### 궁합

화면 위쪽 **사주풀이 / 궁합** 탭으로 오갈 수 있습니다. 어느 화면에서 눌러도 한 번에 그 화면의 입력 폼이 바로 나옵니다.

입력 폼 맨 위에서 **어떤 사이인가요?(연인·부부 / 친구·동료 / 가족)**를 먼저 고릅니다. 두 사람의 이름·성별·생년월일시·태어난 곳을 각각 넣으면(한자 이름은 궁합에서는 받지 않습니다) 아래 내용을 보여 줍니다.

- **띠 궁합(연지)**: 태어난 해의 지지로 보는, 가장 널리 알려진 궁합입니다.
- **일간 궁합**: 일간(하늘의 기운)끼리의 관계로, 성향이나 대화 방식이 얼마나 잘 맞는지를 봅니다.
- **속궁합**: **연인·부부를 골랐을 때만** 다룹니다. 친구·동료나 가족을 골랐으면 이 부분 자체가 나오지 않습니다(설명도 따로 붙지 않습니다 — 그 관계에 맞지 않는 항목이라 자연스럽게 뺀 것입니다). 연인·부부를 골랐어도 **두 사람 모두 만 20세 이상이고 성별이 남·여 한 쌍일 때만** 일지(배우자 자리)·납음오행 내용을 실제로 보여 주고, 조건에 안 맞으면 안내 문구만 나옵니다. 종합 등급을 매길 때도 속궁합을 다루지 않는 경우엔 이 부분을 점수에 넣지 않습니다.
- **서로에게 어떤 자리인지(십성)**: 상대의 일간이 내 일간 기준으로 어떤 십성에 해당하는지(재성·관성·식상·인성·비겁)로, 상대가 나에게 어떤 존재로 느껴지기 쉬운지를 풀어 줍니다. 연애 감정을 전제로 한 표현(예: 편관의 "매력") 몇 곳은 고른 관계에 맞게 다른 문장으로 나옵니다.
- **오행으로 서로 채워 주는 정도**: 내 사주에 필요한 기운(용신·희신)이 상대 사주에 있는지를 봅니다.
- 이 항목들을 종합해 **전반적 일치도**(%)와 좋음·보통·조심 세 등급으로 요약합니다. 퍼센트는 정확히 측정한 확률이 아니라, 위 항목들을 점수로 더해 보기 좋은 수로 옮긴 참고용 숫자입니다(5~95% 사이로만 나옵니다).

만 나이는 두 사람이 입력한 생년월일(양력으로 환산한 날짜)과 오늘 날짜를 비교해 계산합니다.

결과 화면 아래에 사주풀이와 같은 방식의 PDF 저장·인쇄 단추가 있습니다. 궁합 보는 법은 유파·문헌마다 무엇을 더 크게 볼지가 달라, 이 사이트는 흔히 쓰이는 몇 가지 방법을 소개하는 수준으로만 다뤘다는 점을 결과 끝에 적어 두었습니다. 궁합 기록도 사주 기록과 마찬가지로 저장됩니다(고른 관계 유형도 함께 저장). 화면 아래에 오늘 궁합을 본 인원이 표시되고, 관리자 화면의 **궁합 기록** 탭에서 목록(이름 옆에 관계 유형 표시)·검색·삭제와 풀이 다시 보기(PDF 포함)를 할 수 있습니다.

### PDF 저장

결과 맨 아래 **PDF로 저장**을 누르면 A4 PDF 파일이 바로 내려받아집니다. MBTI 사이트와 같은 방식으로, 인쇄 창을 거치지 않고 화면을 직접 PDF로 만듭니다.

- 휴대폰에서 받아도 PC 화면과 같은 모양으로 만들어집니다.
- 문단·표의 한 줄·대운 칸 단위로 쪽을 나누므로 글줄이 쪽 경계에서 잘리지 않습니다. 쪽 아래에는 쪽 번호가 붙습니다.
- PDF를 만드는 도구(html2canvas, jsPDF)는 누를 때 인터넷에서 불러옵니다.
- **카카오톡·인스타그램 등 앱 안 화면(웹뷰) 대응**: 이런 화면은 자동 저장이 막히는 경우가 있습니다. 그런 화면으로 들어온 것 같으면 PDF 단추 위에 안내가 미리 뜨고, PDF를 만든 뒤에는 **'PDF 파일 눌러서 저장'** 단추가 함께 나타납니다. 자동 저장이 조용히 안 됐더라도 이 단추를 사람이 직접 누르면 저장되는 경우가 많습니다. 그래도 안 되면 오른쪽 위 메뉴에서 '다른 브라우저로 열기'를 고른 뒤 다시 시도해 주세요.
- 종이로 뽑을 때는 옆의 **인쇄** 단추를 쓰면 됩니다.

## 5. 문제 해결

| 증상 | 확인할 곳 |
|---|---|
| 풀이는 나오는데 오늘 인원이 "-"로 나옴 | `config.js` 두 값, `schema.sql` 실행 여부 |
| 결과 화면에 "풀이 기록을 저장하지 못했습니다" 표시 | SQL을 실행했는지, MBTI와 **같은 프로젝트**에서 실행했는지 |
| 궁합 결과 화면에 "궁합 기록을 저장하지 못했습니다" 표시 | `schema.sql`을 다시 실행했는지(`gunghap_results` 표가 아직 없을 수 있음) |
| 궁합 기록에 관계 유형이 항상 "연인·부부"로만 나옴 | `schema.sql`을 다시 실행(관계 유형 칸 추가). 실행 전에는 무엇을 골라도 연인·부부로 저장됨 |
| 인증번호 메일이 안 옴 | 스팸함 확인. 짧은 시간에 여러 번 요청하면 Supabase가 잠시 막음. 관리자 주소는 Supabase **Authentication → Users**에도 있어야 함(MBTI 때 로그인한 적이 있으면 이미 있음) |
| "관리자로 등록된 주소가 아닙니다" 표시 | `select email from public.admins;`에 그 주소가 있는지 |
| 인증번호 자릿수가 다름 | Supabase의 OTP 길이 설정과 `config.js`의 `OTP_LENGTH`를 맞춤 |
| 후보 한자 중 일부가 빈 네모(□)로 보임 | 그 기기에 없는 아주 드문 한자체 글꼴 문제입니다. 획수·계산에는 영향이 없고, 흔히 쓰는 한자로 바꿔 골라도 됩니다 |
| PDF 단추를 눌러도 파일이 안 생김 | 인터넷 연결, 앱 안 화면이면 기본 브라우저로 열기 |
| 한자 이름이 관리자 기록에 안 남음 | `schema.sql`을 다시 한 번 실행(한자 이름 칸 추가). 실행 전에도 풀이와 저장은 한자 없이 정상 동작 |
| 화면이 바뀌지 않음 | 브라우저 새로고침(Ctrl+F5). Pages 반영에 1~2분 걸림 |

## 6. 운영 시 주의

- 이름과 생년월일시는 개인정보입니다. 입력 화면의 저장 안내 문구는 뺐으니, 사이트를 재단 밖으로 널리 알릴 때는 저장 사실을 알리는 방법(안내 문구 또는 동의 절차)을 다시 검토하세요. 필요 없어진 기록은 관리자 화면에서 지워 주세요.
- 대운·세운·일진의 '조심' 문구는 요청에 따라 돌려 말하지 않고 직접적으로 씁니다(예: "투자·사업 실패나 과로로 인한 건강 악화... 곤란을 겪을 수 있으니"). 재미로 보는 참고 자료라는 점과 함께, 필요하면 문구 톤을 다시 순화할 수 있다는 점을 알아 두세요.
- 사주 풀이는 재미로 보는 참고 자료입니다. 건강·돈·진로 같은 중요한 결정의 근거로 쓰지 않도록 안내합니다.
- 같은 사주라도 유파(학파)마다 용신·신살 해석이 다를 수 있습니다.
- **Supabase 보안 진단(Advisor)에 뜨는 경고 안내**: `saju_results`·`gunghap_results`(그리고 MBTI의 `mbti_results`) 표의 "RLS Policy Always True" 경고와 `saju_today_count`·`gunghap_today_count`·`today_count`·`is_admin` 함수의 "SECURITY DEFINER" 경고는 이 사이트 구조상 의도한 대로입니다. 누구나 기록을 등록할 수 있어야 하고(등록 정책이 `WITH CHECK (true)`), 등록된 기록은 관리자만 읽을 수 있어야 하는데(조회·삭제 정책은 `is_admin()`으로 막음), 그 확인 함수 자체는 로그인 없이도 호출할 수 있어야 하기 때문에 `SECURITY DEFINER`로 만들었습니다. 함수가 실제로 내주는 값은 오늘 인원 숫자 하나, 관리자 여부(참/거짓) 하나뿐이라 개별 기록이 새어 나가지는 않습니다. 다만 **"Leaked Password Protection Disabled"** 경고는 별개로, Supabase 대시보드 **Authentication → Sign In / Providers**(또는 Auth 설정)에서 켜 두는 것이 좋습니다. 이 사이트는 비밀번호 로그인을 쓰지 않아 지금 당장 영향은 없지만, 켜 둔다고 손해 볼 것도 없습니다.
- 누구나 등록할 수 있는 구조라 짧은 시간에 대량으로 등록하는 방식의 스팸에는 노출될 수 있습니다. 문제가 생기면 관리자 화면에서 지우면 되고, 필요하면 등록 빈도를 제한하는 기능을 추가로 만들어 드릴 수 있습니다.
